# 신규 템플릿/개선 제안 (2026-09-12 실행)

카탈로그에 자동 반영되지 않는 참고용 메모다. 사람이 검토 후 필요하면
`question-gen/config/question-templates.yaml`에 직접 반영한다.

## 1. (버그 수정 제안) `runner/binding.py`의 `_wiki_entities_with_section`이 빈 템플릿 주석을 "내용 있음"으로 오판

`wiki/players/{id}.md`의 `## 별명·밈`·`## 커리어 이력` 섹션에 `<!-- 항목마다: ... -->`
같은 빈 템플릿 주석만 있어도 현재 함수는 "내용 있음"으로 판정해 후보 엔티티 풀에
포함시킨다(오늘 실행에서 50054·50106·50036·50150·50092 등 다수 적중, 결국 생성
단계에서 전부 건너뜀 — casebook good.md #127 참고). HTML 주석(`<!-- ... -->`)을
제거한 뒤 남는 텍스트가 있는지로 판정 조건을 바꾸면, ③ 템플릿 선택 단계에서부터
이런 "빈 후보"를 걸러내 생성 단계의 낭비를 줄일 수 있다.

## 2. (버그 수정 제안) `aggregate_stats.py`의 `_render_table_md`가 "역대 팀 기록" 표에서 행-팀명 매핑을 잃음

`kbo-official.md`의 "역대 팀 기록" 섹션은 연도별로 헤더 행에 "연도+통계라벨+10개
구단명"을 한 줄로 몰아넣고, 실제 데이터 10행에는 구단명 없이 숫자만 있다. 헤더의
구단명 나열 순서와 데이터 행 순서가 실제로 일치하는지는 원시 데이터(kbo_records
소스)를 봐야 확인 가능하고, 렌더된 md만으로는 evidence 인용이 불가능하다(오늘
2020~2025 연도 후보를 이 문제로 전부 포기 — casebook bad.md #53 참고). 각 데이터
행 맨 앞에 구단명 열을 추가해 렌더링하도록 고치면 TEAM_RECORD_HISTORY가 과거 연도도
다시 evidence 검증을 통과할 수 있다.

## 3. (신규 템플릿 아이디어) PLAYER_H2H_STAT — 오늘 두 팀 소속 "라이벌 관계" 선수의 개인 맞대결 성적

오늘 KT 박영현(마무리)과 한화 박정현(내야수, 친형제)의 위키 문서에는 "형 상대 통산
6타수 3안타 2홈런 OPS 2.000"처럼 **구체적인 개인 대 개인 누적 스탯**이 실려 있다.
현재 `RELATION_LINK`는 "공통점이 무엇인가"만 묻지만, 이런 라이벌·형제 관계에서
누적 수치가 확보된 경우엔 "A가 B를 상대로 더 강하다 — O/X" 같은 별도 사실 확인형
문제가 가능하다. `graph.json`의 `라이벌` 엣지 중 개인 통산 스탯이 위키에 명시된
쌍만 골라 쓰면 카탈로그 부담 없이(엣지 자체가 이미 희소함, EXPERT 유지) 소재
다양성을 늘릴 수 있다.

## 4. (신규 템플릿 아이디어) BATTING_RACE — 시즌 타율/평균자책점 상위권 두 선수의 순위 비교

오늘 롯데 레이예스(타율 0.345, 리그 2위)와 삼성 구자욱(0.363, 1위)처럼, 두 선수가
`kbo-official.md` 타자/투수 기본기록 표에서 **모두 상위 10위 안에 들어 있는 경우**
"둘 중 누가 더 순위가 높은가?"를 BINARY로 물을 수 있다. 오늘은 이 소재를
`RELATION_LINK`(공통점=타격왕 경쟁)로 우회 출제했지만, 수치 자체를 직접 비교하는
전용 템플릿이 있으면 검증(수치 비교는 결정적으로 재확인 가능)도 더 쉬워진다.
